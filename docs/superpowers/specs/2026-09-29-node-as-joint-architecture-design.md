# Node as Joint Architecture — Design

## Authority, intent, and boundary

Product Owner decisions D-NODE-JOINT-APPROVAL-01/02/03/04 approve explicit Member–Node incidence, legacy same-coordinate distinct Nodes, blocking ambiguous migrations, and consistency between a visible Joint and every member passing through it in normal v2 editing. This specification follows the architecture review of `feat/structural-sketch-visual-language` at `e9702e7`; that branch contains the Structural Sketch and incomplete-Draft UX work and is not merged by this design.

The student should model a 2D pin-jointed truss with one visible concept for a structural joint: **节点**. A Node has a stable identity and coordinates. A PhysicalMember participates at its referenced start/end Nodes and at explicitly recorded intermediate Nodes. In normal v2 editing, one visible Node is a complete Joint: every member that geometrically passes through it must participate. The teaching rules are **“有节点才连接；没有节点，交叉也不连接。”** and **“节点表示这里的构件真正相连，可以传力。”** A crossing without a Node is not connected.

For both new and migrated models, equal coordinates alone never imply equal Node identity. Participation requires the *same Node identity* plus an endpoint reference or intermediate incidence. Geometry may help **discover** topology; geometry does not **author** topology in Solver, Idealizer, or Snapshot. In normal v2 editing, if a visible Node lies on a member, the editor must explicitly author that member's participation as part of the confirmed edit; a crossing with no Node never gains one by inference. Legacy nonparticipating overlaps are preserved only as marked migration exceptions. PhysicalMember remains one physical object even when Idealizer creates several analysis elements.

This change affects editable-Draft topology, snapshots, idealization, learning/report adapters, and Canvas presentation. It does **not** change Truss2DSolver, `truss2d-input-v1`, 2D linear-elastic pin-jointed axial-only mechanics, `EA/L`, global ux/uy, sign conventions, PINNED/ROLLER X/Y semantics, or units `mm / N / MPa / g`. No fixed support, distributed load, moment, or rigid joint is introduced.

## Chosen architecture and alternatives

Approach B is authoritative. Splitting a PhysicalMember at each joint (A) would simplify a solver graph but break the student's one-member identity, report provenance, and material/section ownership. Pure coordinate inference (C) would create hidden topology and make crossing-without-Node unstable under tolerance, save/reload, and editing. B keeps endpoint Node references and adds explicit intermediate Member–Node incidence; analysis segmentation stays downstream of the immutable physical snapshot.

The internal Django class may remain `GeometryNode`; a rename is not a prerequisite. Student UI always calls it **节点**, and there is no editable Connection or student-facing “连接” tool. Any v1 Connection reader is a legacy compatibility component, not a second editable topology authority.

## Editable domain and invariants

- `GeometryNode`: project-scoped stable `client_key`, finite `x_mm`, `y_mm`, and label. Identity, not coordinate equality, defines a joint. Nodes may exist before a member is attached. Same-coordinate distinct identities are permitted only for documented legacy topology and must survive round-trip unchanged.
- `PhysicalMember`: stable identity, nullable start/end Node references (for incomplete Draft), nullable Material/Section, label, and existing active flag. A non-null endpoint reference is explicit participation of that member at that Node. Start and end must be distinct identities and have nonzero geometric length before analysis. Existing `is_active` behavior is preserved; this work does not redefine it.
- `MemberJointIncidence`: project-owned through record with stable member and Node references, representing **only intermediate** participation. `(member, node)` is unique; the Node and member must belong to the same project. It is not a separately selectable student object. No `position` or array index is topology authority. A complete incidence requires a valid member and Node; an edit that removes either endpoint of the relation removes that incidence explicitly in the same edit transaction rather than creating a ghost relation.
- `Support` and `NodeLoad`: nullable `target_node` FK with `SET_NULL`, replacing `target_connection`. Their values and types do not change. Deleting a target Node keeps the Support/Load as an incomplete Draft object with a null target. A Node carrying a Support/Load must participate in at least one analyzable member before snapshot generation; merely sharing coordinates with a member is insufficient.
- Material/Section owner checks, project ownership, physical member identity, and the existing independent-delete policy remain. Connection and ConnectionParticipation leave the v2 editable model only after guarded data conversion; historical JSON does not change.

The v2 save validator enforces project/owner scope, unique keys, finite numbers, no duplicate incidence, resolvable non-null references, and the normal-model pass-through invariant: every member geometrically passing through a Node must reference that Node as an endpoint or have an intermediate incidence. `MEMBER_PASSES_THROUGH_NODE_WITHOUT_INCIDENCE` rejects a crafted/stale v2 save; Model Check uses the same code for an imported/corrupt stored Draft and explains “构件 M3 经过节点 N2，但尚未建立节点关系。” This is an integrity error, **not** a permissive incomplete-Draft state. If member endpoints are missing, check those first and defer pass-through geometry validation until the segment exists. Save never repairs topology by inference.

New normal editor actions reuse an existing Node identity only after deliberate selection and do not manufacture a second Node at the same coordinate. The server permits exact same-coordinate distinct identities and nonparticipating pass-through pairs recorded in a project's immutable legacy migration mapping (including pre-existing distinct GeometryNodes), so migrated Drafts can save/reload without changing old topology. These exemptions are keyed to the old Node/member identities and audited geometry; they do not authorize new pairs, moved overlaps, or new same-coordinate duplicate identities. A legacy exception is visibly labeled as non-connected, never presented as an ordinary Joint. Moving a legacy pair apart does not authorize a new pair elsewhere.

## Intermediate ordering and geometry

For each complete member, the start Node has parameter `t=0`, the end Node `t=1`, and each explicit intermediate incidence gets `t = dot(P-A, B-A) / |B-A|²`. Validate collinearity and range using the current v1 Idealizer's effective tolerances (`abs(cross) <= 1e-9 * max(1, member length)`, `-1e-12 <= t <= 1+1e-12`) to avoid broadening topology acceptance during migration. Intermediate `t` must be strictly between the endpoint tolerances; no two incident Nodes may have `|Δt| <= 1e-12`. A duplicate position, even with different Node IDs, is an invalid zero-length analysis segment. Sort by numeric `t`, then stable Node key only for deterministic diagnostics; key order never resolves a geometric tie.

The editor uses screen-space hit tolerance only to *offer* candidate members and Nodes. At commit it enumerates **all** actual Node/member pass-through pairs under the strict geometry rule, then writes the necessary endpoint reference or intermediate incidence in the same atomic edit. The server independently checks the complete Draft graph; the Idealizer reads only those explicit relations. A snapped intersection point must be computed and stored consistently so every committed incidence passes the strict check. Visual snap LOD and the 1 mm grid do not alter this authority or round decimal coordinates.

## Canvas creation and edit contract

The tools are **选择、节点、构件、支座、荷载**. At a crossing without Node, show a non-topological preview: “在交点建立节点，将连接这里经过的构件”, including the verified member count. A click confirms one Node plus an explicit incidence for **every** member that strictly passes through that point, including 3+ members, as one atomic editor action. The user cannot pick only a subset at one visible Joint; to leave a member disconnected they must not place a common Node there or must change the geometry. Without confirmation, a geometric crossing remains unmarked and disconnected in Draft, Snapshot, and analysis.

Placing a Node on a single member interior explicitly creates its incidence in the same action. Creating or confirming a Node at any location attaches **all** strictly passing existing members, not a selected subset; the preview lists/counts them before the user's confirmation. If a new member's path crosses an existing Node N3, the pre-commit UI says “构件经过已有节点 N3，将在这里形成连接。” Completing the member explicitly writes `MemberJointIncidence(member, N3)`, or an endpoint reference if N3 is its endpoint. When several existing Nodes lie on the path, preview and attach each distinct normal Node. Merely crossing another member where there is **no** Node does not attach either member. Support/Load tools select a Node directly and must not create topology as a side effect.

Node dragging previews the proposed coordinates but **rejects commit** if any of that Node's explicit intermediate incidences would become off-member, or if moving a member endpoint would make another explicit incidence invalid, create a zero-length member, create duplicate incident positions, or introduce an unrepresented member-through-Node pass. The original Draft stays unchanged and the UI names the blocking member/Node and instructs the user to remove/rebind incidence or make an explicit Node/member edit first. This is the movement policy; no silent detach, reattach, clamping, or inference after save. Coordinate edits through Properties and numerical input use the same validator. A valid endpoint move updates geometry while retaining all explicit identities.

For legacy same-coordinate distinct Nodes, render separate identity cues/labels and a visible warning: “这里有多个位置相同但彼此不连接的旧模型节点。” For any audited legacy member-through-Node nonparticipation, show a distinct non-connected legacy cue as well. Hit selection opens an identity chooser listing each Node and its incident/nonincident passing members, Supports, and Loads. It never auto-merges them or paints one ordinary joint marker that conceals the distinction. The chooser is presentation only; it is not a Connection object. Creating a new Node at such an ambiguous legacy overlap is blocked until the identities are explicitly resolved; no automatic merge or reinterpretation is permitted.

Deleting a Node removes only that Node: member endpoint references become null; its intermediate incidences are removed; Supports/Loads targeting it become null and remain independently editable. Deleting a member removes only that member and its incidences; other Nodes, Supports, and Loads remain. Multi-select Delete/Backspace and the Properties delete button share this safe atomic action. If a member deletion leaves a Node with a Support/Load but no participating member, Model Check reports it. Rebind controls can assign missing member endpoints and Support/Load targets; a user can explicitly re-create a valid intermediate incidence. No dangling or fake Node is rendered.

Undo/Redo stores the whole v2 Draft including endpoint keys, intermediate incidences, and target Node keys. Node creation plus selected incidences, deletion plus nulling dependent references, and rebind are each one history entry. Undo restores original identities and references; redo reapplies them. Save/reload preserves client keys and the incidence set. Selection state is pruned when an object disappears, and an incidence is never exposed as a selected object.

## `physical-draft-v2` contract and persistence

The v2 wire Draft has `schema_version: "physical-draft-v2"`, `version`/`expected_draft_version`, and arrays `nodes`, `physical_members`, `member_joint_incidences`, `supports`, `node_loads`. A member retains `start_node_client_key` and `end_node_client_key` plus existing material/section/label/active fields. Each incidence is `{member_client_key, node_client_key}`; its pair is its stable wire identity and list order is irrelevant. A Support/Load has nullable `target_node_client_key`; no `connections` collection or `target_connection_client_key` appears. Null member endpoints, materials, sections, and Support/Load targets remain valid editable Draft states. Invalid or stale non-null references and unrepresented normal Node/member pass-throughs are rejected, not changed or auto-repaired. Legacy exception authority is server-side migration audit, never a client-provided exemption flag.

Save is a project-locked, atomic whole-Draft replacement with the existing optimistic `draft_version` check. It validates before and during the transaction, rebuilds leaves before roots safely, and increments version once. Workspace bootstrap serializes the same v2 graph. A stale browser's v1 payload is rejected with an explicit schema/version response and reload guidance; it cannot recreate Connection rows after conversion. A blocked legacy project is not served to the v2 editor as if conversion succeeded.

## Model Check and snapshot boundary

Model Check remains permissive for missing references during editing and strict for analysis. It reports missing member start/end, Material/Section, missing Support/Load Node, invalid/off-member/duplicate intermediate incidence, zero-length member, Support/Load on a Node with no participating analyzable member, and `MEMBER_PASSES_THROUGH_NODE_WITHOUT_INCIDENCE` for an unexempted stored inconsistency. Issues carry stable code, student wording, and the owning PhysicalMember/Support/Load/Node for Canvas focus or the persistent incomplete-object panel. Normal save rejects the latter structural-integrity error; Model Check catches it if data arrived through stale import/migration corruption. The old `MISSING_CONNECTION_*` codes and “未完成连接” category do not occur for v2. Analyze runs the same preflight under project lock and creates no ModelRevision, AnalysisRun, or solver call if incomplete.

Only a complete v2 Draft that has passed the member-through-Node consistency check can freeze `physical-snapshot-v2`. It contains sorted Node records, physical members with endpoint Node IDs, their frozen Material/Section numeric values, sorted explicit intermediate `{member_id,node_id}` incidences, and Supports/NodeLoads targeting Node IDs. It includes the existing analysis type and canonical units. It has no Connection array and performs no topology repair. Ordering and canonical serialization are deterministic; its hash is a new revision hash and is not expected to match a v1 hash for equivalent mechanics.

The v2 Idealizer creates an analysis node for each *participating Node identity* (`node:<client_key>` or an equivalent collision-safe namespace), never by coordinate. It segments each PhysicalMember at ordered intermediate incidences and retains analysis-member-to-PhysicalMember and reverse provenance. A crossing without Node/incidence produces separate analysis nodes and no shared DOF. It reads only explicit endpoints/incidences; even an unexpected overlapping coordinate in a supplied Snapshot does not cause it to add a joint. A Support/Load maps to its participating Node's analysis node. The v1 Idealizer remains available by `schema_version` for immutable historical snapshots. The TrussModel and Solver input schema remain `truss2d-input-v1`.

## Prediction, comparison, reports, and visual results

New predictions use `prediction-v2`: maximum-displacement location references a Node ID; representative load path alternates Node and PhysicalMember IDs, with each adjacent Node pair explicitly incident to that member and adjacent in its ordered analysis segmentation. Existing member judgments remain keyed by PhysicalMember. Prediction creation/completion and analyze eligibility dispatch by the current Draft version and reject stale version/schema combinations. Previously stored `prediction-v1` payloads remain immutable and are interpreted only through the v1 historical path.

Comparison and explanation dispatch on revision snapshot/prediction schema, not the present editable Draft. v1 `CONNECTION` and `free_endpoint` provenance remain readable; v2 uses Node provenance. Old report packages continue to show their original explicit connections; new reports show structural Nodes and intermediate incidences without a “显式连接” count. Historical ModelRevision, AnalysisRun, solver input/results, Prediction, Reflection, Reasoning, and report semantics are neither rewritten nor recomputed from current Draft. Result overlays use versioned provenance so student selection maps to the correct physical Node or member in either schema.

The Structural Sketch retains hollow Node, member body, PINNED/ROLLER X/Y, and correctly anchored Fx/Fy arrows. It removes the explicit Connection ring, Connection render layer, Connection hit priority, and Connection selection identity from v2. The Node symbol itself is the Joint symbol: in a normal v2 Draft, a Node visibly on a member must have that member's explicit participation. An unexempted inconsistent Draft is not rendered as an ordinary complete Joint; show an error cue and block save/analysis until repaired. Audited legacy nonparticipation has its separate warning cue. Ordinary/shared/selected/result Nodes may receive distinct presentation states, but these are styles of one Node object. Decorations remain `pointer-events: none` and never participate in snap, hit testing, selection, or topology. A crossing without Node has no joint symbol.

## Legacy migration and ambiguous-project policy

Migration is per Project, not a global destructive rewrite. A preflight records a canonical copy/hash of the current editable v1 Draft (including Connection rows, participation slots and nulls), project identity/version, counts, complete/partial classification, and an old-analysis-topology signature. This durable audit is separate from immutable historical revisions. It records every old Connection/endpoint → new Node/incidence mapping and any generated legacy Node keys. Generated keys are deterministic and checked for collision; repeated preflight or retry yields the same proposal.

For each complete Connection with a location and valid participating members, give that old Connection one new Node identity. Each participation at a member endpoint maps that endpoint reference to that Node; each interior participation becomes `MemberJointIncidence`. Supports/Loads targeting the Connection target that Node. If multiple old Connections share one GeometryNode but represented independent old analysis DOFs, give them distinct new Node identities at that coordinate. Each old free endpoint (`free:<member>:START/END`) remains its own analysis-identity class even when multiple endpoints reference the same old GeometryNode; create same-coordinate distinct legacy Nodes as needed. A geometry-only old Node with no analysis participation may remain a standalone Node. The mapping preserves labels/positions and never merges distinct old DOFs. Any migrated member that geometrically passes a different legacy Node without participation is recorded as a specific audited exception and receives a non-connected visual cue; v2 validation permits only that unchanged identity/geometry pair. Migration never adds its incidence merely to satisfy the normal-model rule. A complete Connection that cannot be placed on a claimed member, would create a duplicate segmentation position, or cannot be mapped to exactly one old DOF is blocked, not approximated.

For an incomplete Connection, use only explicit surviving fields and references. If it uniquely identifies a Node, member participation, and Support/Load target, migrate those fields deterministically and record the source. If a null participant slot or missing location leaves more than one plausible topology or target, **block that Project**; preserve the complete legacy payload, recoverable fields, reason, and counts in the audit, without guessing a nearest point, making a ghost Node/incidence, dropping a meaningful slot, or changing existing targets. A located Connection with no valid member participation is not treated as an analyzable joint; if it carries a Support/Load or a meaningful incomplete slot, it blocks automatic migration. An obsolete Connection with no location, no valid participation, no Support/Load reference, and no other recoverable structural meaning may be removed only with an explicit audited `OBSOLETE_EMPTY_CONNECTION` classification; no other incomplete Connection is silently dropped.

Blocked Projects retain their v1 editable rows and immutable history, are flagged as migration-blocked, and are shown a read-only legacy/recovery view with the reason and an export of their preserved Draft. Their v2 editor, Model Check, and Analyze are not enabled until an authorized, explicit resolution produces a unique mapping and the same preflight/equivalence gates pass. No automated retry changes their topology. The legacy table/reader stays present through this transition; it is not dropped merely because some projects migrated. This is a per-Project safety stop, not a full-platform data deletion.

Conversion acquires the Project row lock shared by save/analyze, rechecks `draft_version` and the preflight payload hash, writes v2 graph and audit in one transaction, increments `draft_version` once, and marks that Project v2 only after validation/equivalence succeeds. Concurrent v1 edits force preflight restart; stale browser saves fail. A migration failure rolls back that Project's changes completely. Operational purge must include the new incidence and migration-audit entities in dependency-safe order, retaining whatever minimal durable purge receipt policy already applies.

Rollout gates are: deploy readers/audit and dual-schema dispatch first; run read-only inventories; convert eligible Projects behind a per-Project schema switch; enable v2 editor only for converted/new Projects; retain blocked v1 recovery path; retire editable Connection code only after all Projects are resolved. Rollback of application code keeps v1 history readable. Rolling back a converted Project requires pausing writes and restoring its audited pre-conversion v1 Draft under lock; if v2 edits occurred, capture and present that newer Draft for explicit owner disposition first—never silently overwrite it. Dropping legacy tables or the audit is outside this change.

## Numerical equivalence and acceptance

For each migratable complete legacy model, idealize its frozen v1 candidate and the proposed v2 snapshot before cutover. Compare analysis graph **by old-to-new identity mapping**, not raw IDs or hashes: same connected components, segment geometry and PhysicalMember provenance, E/A, Support ux/uy restraints, and Fx/Fy loads. Run the unchanged Solver on both and compare node displacement, reaction, axial force, stress, and mass using component-wise `abs_tol=1e-8` and `rel_tol=1e-8` in their canonical units. A mismatch blocks that Project. Singular/invalid v1 models must retain their old diagnostic behavior or be blocked for explicit resolution; a new successful result is not assumed equivalent to an old failure.

Acceptance tests explicitly require these seven cases: **(1)** two members cross without Node → not connected; **(2)** create a Node at their crossing → one Node, two explicit incidences, connected; **(3)** three members pass the same crossing before Node creation → all three explicitly participate; **(4)** draw a new member through an existing Node → explicit intermediate incidence (or endpoint reference); **(5)** craft/save a normal v2 payload whose member passes a Node without participation → `MEMBER_PASSES_THROUGH_NODE_WITHOUT_INCIDENCE`, save fails; **(6)** migrated same-coordinate distinct legacy Nodes and audited nonparticipating passes retain separate identities and old topology; **(7)** the v2 Idealizer processes a valid Snapshot using only explicit incidences and never geometry-based topology inference. Also cover a two-member endpoint joint, one PhysicalMember split into AnalysisElements, duplicate-position rejection, endpoint/intermediate move validation, Support/Load target and independent deletion/rebind, atomic undo/redo, save/reload, stale concurrent save, incomplete migration block and audited empty-Connection removal, v1 historical report/prediction/comparison/explanation, v2 report/result provenance, and full solver numerical equivalence. Browser tests verify the crossing preview requires a click, 3+ member joint preview, through-existing-Node confirmation, legacy identity chooser/warnings, no Connection tool/ring, and symbols/decorations do not create topology. Full non-browser/browser regression, Django checks, migration checks, and diff check are required before any implementation completion claim.

## Risk controls and non-negotiable invariants

The highest risk is inadvertently merging old free endpoints that shared a GeometryNode; the identity-class mapping and pre-cutover graph comparison address it. Other risks are silent conversion of incomplete Connection slots into a falsely complete Draft, partial visual joints in normal v2 models, loss of audited legacy nonparticipating passes, stale tabs rewriting v1 rows, and v2-only consumers breaking immutable v1 teaching history. Each is a blocking acceptance gate, not a warning to waive.

At every layer, same coordinate is not same Node; same Node identity plus member endpoint/incidence is joint participation; crossing without Node is not connected. In normal v2 editing, every member passing through a visible Node participates in it via persisted explicit reference/incidence. Geometry may discover candidate topology, but only a confirmed editor operation writes it; Save/Model Check verify consistency, while Snapshot/Idealizer never infer or repair it. Audited legacy exceptions preserve old topology and are visually distinguished, not generalized into new modeling UX. Editing may be incomplete in nullable references, but structural pass-through inconsistency is invalid; Snapshot/Analyze remain strict. PhysicalMember identity and historical artifacts remain stable. Solver and canonical mechanics do not change.
